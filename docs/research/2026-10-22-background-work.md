# Background computer use and bounded plans

The requested behavior is to keep the visible workspace, focus, pointer and clipboard undisturbed while work proceeds on explicitly scoped targets; make file selection dependable; prepare 4–10 steps ahead and execute until an observation requires replanning. A reserved workspace alone does not isolate global keyboard or mouse input.

## Sources and decisions

- The installed grim supports `-T IDENTIFIER`. The compositor advertises foreign toplevel listing, Hyprland mapping and image capture protocols. The [mapping protocol](https://github.com/hyprwm/hyprland-protocols/blob/main/protocols/hyprland-toplevel-mapping-v1.xml) associates full 64-bit window addresses with foreign toplevels. Truncating an address to the older 32-bit export handle is incorrect. A small native helper enumerates bounded mappings without focus/input requests. Protocol XML retains its original licenses.
- Default window capture now reads the surface directly, even on an inactive workspace. Unsupported capture fails instead of focusing. An explicit `allowFocus` flag retains the legacy route. Workspace capture returns a private image set and positions, not an exact compositor scene with wallpaper, panels, stacking and effects. This does not guarantee application rendering freshness; inspect the actual image and wait for application readiness.
- The installed Open Browser Use bridge was already connected. Saarthi uses its explicit local profile socket as an optional per-invocation client. No new daemon, HTTP endpoint or MCP server was added. [Upstream source](https://github.com/iFurySt/open-browser-use/blob/main/apps/chrome-extension/src/background.js) creates physical tabs with `active:false`; the session's `active:true` field is logical selection. Session ownership never authorizes claiming unrelated user tabs.
- Direct `DOM.setFileInputFiles` failed with `Not allowed` on this profile. [Chromium's DOM handler](https://github.com/chromium/chromium/blob/main/content/browser/devtools/protocol/dom_handler.cc) rejects file-path access when its file-access capability is false. The adapter instead transfers explicitly selected file bytes through fixed programs, builds [File objects](https://developer.mozilla.org/en-US/docs/Web/API/File/File), assigns a DataTransfer file list once and dispatches input/change events. Small batches share one transfer request; larger files use bounded chunks. Browser permissions remain unchanged. Sites requiring trusted native events may need a different supported workflow.
- Plans accept 4–10 typed steps, require explicit target scope and a checkpoint after each browser mutation, and share one browser connection/session lease. Native captures additionally check PID/workspace. The caller supplies the reasoning. A durable receipt records intent before each step; an existing id always refuses replay. Native global input remains outside the background executor.

## Live verification

These are functional integration checks, not autonomous benchmark results.

1. Silent policy-approved Zathura launch on workspace 4 preserved the focused terminal on workspace 2. A subsequent launch opened the public W3C dummy PDF on workspace 4. Surface capture first showed the application's loading state; a later capture showed the rendered PDF while the terminal retained focus. Both PNGs were visually inspected. Capturing a loading state is not proof of a rendered document.
2. An eight-step browser workflow filled a title, observed its application update, attached four explicitly selected files to a hidden multiple-file input, observed all four payloads in the page, built a preview, verified its text, read the attachment list and captured the background tab. It completed in 11,480 ms, followed by workspace-4 capture in 1,110 ms. Across 159 foreground samples, focus/workspace/pointer were unchanged; the preferred clipboard payload hash and unrelated tab metadata were unchanged. The page was a controlled fixture in the user's real connected browser, not an independent real-world agent task.
3. A separate successful eight-step execution took 3,883 ms, but its surrounding preservation check was invalidated by desktop movement and a missing surface mapping in a later workspace capture. It is not counted as a complete preservation pass.
4. A later repeat completed seven editing/checkpoint steps and timed out at browser-tab screenshot capture. A read-only screenshot retry also timed out while the browser window was on an inactive workspace. The adapter now reports `ACTION_TIMEOUT`, does not focus as a fallback, and never replays preceding mutations. Browser-tab screenshot reliability remains a limitation distinct from successful native window capture.
5. Initial live checks exposed a missing debugger attach and an incorrect JSON-key-order comparison. Both were fixed and covered by regression checks. Direct file-path access was replaced after the verified Chromium refusal. One development retry was invalid because the linked build was rebuilt during execution; final checks use a completed build.

6. The final completed-build check used the small-file bundle route and ended with DOM inspection instead of a browser screenshot. Eight steps completed in 10,786 ms while a separate desktop-input lease was held; workspace-4 surface capture took 665 ms. All 131 foreground samples matched, as did clipboard hash and unrelated tab metadata. This confirms background execution does not contend for the global input lease. It is a different terminal observation from the earlier screenshot plan, so the two timings are not a speedup comparison.

Local checks passed: 231 Vitest tests across 33 files, the native mapping-helper build, a frozen Bun install, and built CLI smoke for all 75 help commands plus 31 read-only JSON commands.

Private run files and screenshots remain local. Do not publish user page text, clipboard contents, session sockets or unrelated tab URLs. The existing 64-case GTK suite remains synthetic integration coverage. The 56 real-application challenge designs are unrun, and no independent Codex/autonomous score is claimed.
